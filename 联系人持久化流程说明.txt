联系人持久化流程说明
====================

本文说明 crm.py 中一条新增联系人记录如何从命令输入保存到 SQLite，
再被后续查询读取。文中所有带输出的例子均于 2026-10-06 在本仓库目录
实际执行并核对（执行环境：Python 3，工作目录为本说明所在目录）；
未实际执行的例子会明确标注为"预期结果"。

本文仅为代码理解成果，不修改 crm.py、数据库结构、tests/ 与 README.md
的任何行为与内容。文中引用的函数均指 crm.py 中的同名函数。


一、新增记录（add）的完整执行顺序
---------------------------------

以如下命令为例：

    python crm.py --db ../contacts.sqlite3 add --name 林宁 --email lin@example.test --company 星河科技

注意：--db 是全局参数，由顶层解析器定义（见 build_parser() 中
parser.add_argument("--db", ...)），必须写在子命令 add 或 list 之前；
写在子命令之后会被 argparse 拒绝。

执行顺序如下，每一步对应 crm.py 中的源码函数：

1. 参数解析
   入口 main() 调用 build_parser() 构建解析器，再用
   parser.parse_args() 解析命令行。解析结果中 args.func 指向
   cmd_add，args.db / args.name / args.email / args.company 分别
   保存各参数值。main() 随后调用 args.func(args)，即进入 cmd_add()。

2. 字段清理
   cmd_add() 对三个字段分别调用 clean()。clean() 只做
   value.strip()：去掉首尾空白，保留内部字符与大小写。
   例如 "  林宁 " 变为 "林宁"，而 "Xu@Example.TEST" 原样保留。

3. 字段校验（在打开数据库之前完成）
   cmd_add() 依次检查：
   - 姓名为空      -> fail("name", "must not be empty")
   - 邮箱不合规    -> fail("email", "invalid email address")
                      规则见 valid_email()：无空白字符、恰好一个 @、
                      @ 两侧非空、域名至少含一个点且各段非空。
   - 公司为空      -> fail("company", "must not be empty")
   校验按姓名、邮箱、公司的顺序进行，多个字段同时无效时只报告
   首个错误。fail() 把 "字段: 消息" 打印到标准错误并以退出码 2
   结束进程，标准输出为空。
   关键结论：以上校验全部发生在 connect_db() 之前，因此输入被
   拒绝时根本不会打开数据库——新数据库文件不会被创建，已有
   数据库中的记录保持不变。

4. 数据库初始化
   校验通过后，cmd_add() 调用 connect_db(args.db)。
   connect_db() 先用 Path(db_path).parent.is_dir() 检查父目录：
   父目录不存在时调用 fail("db", "parent directory does not exist")
   （退出码 2），不会代为创建目录。父目录存在时用
   sqlite3.connect() 打开（文件不存在则新建）数据库，并执行
   CREATE TABLE IF NOT EXISTS contacts（常量 CREATE_TABLE_SQL）
   后提交。表结构为：
       id      INTEGER PRIMARY KEY AUTOINCREMENT
       name    TEXT NOT NULL
       email   TEXT NOT NULL
       company TEXT NOT NULL
   已存在的数据库与表会被原样复用，已有记录不受影响。

5. 提交写入
   cmd_add() 用参数化语句
       INSERT INTO contacts (name, email, company) VALUES (?, ?, ?)
   插入清理后的三个字段，随后 conn.commit() 提交事务，最后在
   finally 块中 conn.close()。id 由 SQLite 的 AUTOINCREMENT 分配，
   本例中依次得到 1、2、3。

6. JSON 输出
   提交成功后，cmd_add() 用 cursor.lastrowid 取回新记录的 id，
   组装字典并以 json.dumps(..., ensure_ascii=False) 打印到标准
   输出（单行 JSON，非 ASCII 字符不转义），返回 0。


二、查询记录（list）的执行顺序
------------------------------

以如下命令为例：

    python crm.py --db ../contacts.sqlite3 list --company 星河科技

1. main() 解析参数后进入 cmd_list()。
2. cmd_list() 同样先 clean() 公司名；清理后为空则
   fail("company", "must not be empty")（退出码 2）。
3. connect_db() 打开同一个数据库文件（必要时初始化表）。
4. 执行参数化查询：
       SELECT id, name, email, company
       FROM contacts WHERE company = ? ORDER BY id ASC
   WHERE company = ? 是精确匹配（清理后的公司名与存储值完全相等
   才命中），结果按 id 升序排列。
5. 把每行组装为字典，以 JSON 数组打印到标准输出；无匹配时输出
   空数组 []。

为什么独立进程也能读到之前新增的记录：每条命令都是一次独立的
python 进程，进程结束时连接已关闭；但 add 在关闭前已 commit，
记录被持久化到 ../contacts.sqlite3 文件中。后续 list 进程通过
connect_db() 打开同一个文件，读取的是已提交的数据，因此跨进程
查询结果一致。这正是"每条命令视为独立进程、共用同一数据库文件"
仍能工作的依据。


三、固定例子（均已实际执行核对）
--------------------------------

前提：父目录 .. 已存在；首次执行前 ../contacts.sqlite3 不存在，
由第一条 add 命令自动创建。以下命令逐条在独立进程中执行，共用
同一个数据库文件 ../contacts.sqlite3。

1) 新增星河科技的林宁

    python crm.py --db ../contacts.sqlite3 add --name 林宁 --email lin@example.test --company 星河科技

   实际标准输出（退出码 0）：

    {"id": 1, "name": "林宁", "email": "lin@example.test", "company": "星河科技"}

2) 新增星河科技的许禾

    python crm.py --db ../contacts.sqlite3 add --name 许禾 --email xu@example.test --company 星河科技

   实际标准输出（退出码 0）：

    {"id": 2, "name": "许禾", "email": "xu@example.test", "company": "星河科技"}

3) 新增远帆咨询的周岚

    python crm.py --db ../contacts.sqlite3 add --name 周岚 --email zhou@example.test --company 远帆咨询

   实际标准输出（退出码 0）：

    {"id": 3, "name": "周岚", "email": "zhou@example.test", "company": "远帆咨询"}

4) 查询星河科技：返回林宁、许禾两人，按编号升序

    python crm.py --db ../contacts.sqlite3 list --company 星河科技

   实际标准输出（退出码 0）：

    [{"id": 1, "name": "林宁", "email": "lin@example.test", "company": "星河科技"}, {"id": 2, "name": "许禾", "email": "xu@example.test", "company": "星河科技"}]

5) 查询远帆咨询：只返回周岚

    python crm.py --db ../contacts.sqlite3 list --company 远帆咨询

   实际标准输出（退出码 0）：

    [{"id": 3, "name": "周岚", "email": "zhou@example.test", "company": "远帆咨询"}]

6) 查询未匹配的公司：返回空数组

    python crm.py --db ../contacts.sqlite3 list --company 不存在的公司

   实际标准输出（退出码 0）：

    []


四、输入被拒绝时不会产生联系人（均已实际执行核对）
------------------------------------------------

以下每条命令的退出码均为 2，标准输出为空，错误信息写到标准错误；
被拒绝的输入不会写入任何记录。

1) 空白姓名

    python crm.py --db ../contacts.sqlite3 add --name "   " --email lin@example.test --company 星河科技

   实际标准错误：

    name: must not be empty

2) 无效邮箱（缺少 @ 与域名）

    python crm.py --db ../contacts.sqlite3 add --name 林宁 --email lin.example.test --company 星河科技

   实际标准错误：

    email: invalid email address

   已核对：字段校验在打开数据库之前完成（cmd_add() 中校验先于
   connect_db()）。把 --db 指向一个不存在的新文件执行本条命令，
   该文件不会被创建；指向已有数据库时，已有记录保持不变。

3) 空白公司

    python crm.py --db ../contacts.sqlite3 add --name 林宁 --email lin@example.test --company "  "

   实际标准错误：

    company: must not be empty

4) 多个字段同时无效：按姓名、邮箱、公司的顺序只报告首个错误

    python crm.py --db ../contacts.sqlite3 add --name " " --email bad --company " "

   实际标准错误（邮箱与公司同样无效，但只报告姓名）：

    name: must not be empty

5) 字段全部有效但父目录缺失

    python crm.py --db ../no_such_dir/contacts.sqlite3 add --name 林宁 --email lin@example.test --company 星河科技

   实际标准错误（退出码 2，标准输出为空）：

    db: parent directory does not exist

   已核对：程序不会创建缺失的目录，../no_such_dir 在执行后仍不
   存在。该检查位于 connect_db() 开头，发生在 sqlite3.connect()
   之前。


五、关键结论与源码对应
----------------------

- 参数解析：build_parser() 定义全局 --db 与 add/list 子命令，
  main() 负责解析并分派到 cmd_add() / cmd_list()。
- 字段清理：clean() 仅 strip() 首尾空白，内部字符与大小写保留。
- 字段校验：cmd_add() 内联检查非空，valid_email() 检查邮箱；
  校验在 connect_db() 之前，故被拒绝的输入不触碰数据库。
- 错误报告：fail() 统一向标准错误输出 "字段: 消息" 并以退出码
  2 结束，标准输出保持为空。
- 数据库初始化：connect_db() 先检查父目录存在，再连接并执行
  CREATE_TABLE_SQL（CREATE TABLE IF NOT EXISTS），已有数据库
  直接复用。
- 提交写入：cmd_add() 中 INSERT 后立即 conn.commit()，记录随
  事务提交持久化到数据库文件，这是后续独立进程能查询到的依据。
- JSON 输出：cmd_add() 输出单行 JSON 对象，cmd_list() 输出
  JSON 数组，均 ensure_ascii=False，中文字段原样显示。
- 公司筛选：cmd_list() 中 WHERE company = ? 为精确匹配，
  ORDER BY id ASC 保证按编号升序。
